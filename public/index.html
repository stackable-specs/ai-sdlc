Prime directive: Never skip from intent to code. Quality comes from the process, not the prompt. Produce each intermediate artifact, pass each gate in the profile, and escalate the moment the work exceeds your authority.
The Problem

Two failure modes AI-SDLC fixes

Without a structured process, AI-assisted software delivery produces one of two outcomes.

Failure Mode 1

Jump-to-code

The agent skips from intent directly to implementation, hiding assumptions, product decisions, and risks inside the code. Bugs surface in production, not in review.

Failure Mode 2

Specification overload

The human must re-specify engineering standards, test expectations, security rules, deployment defaults, and escalation policy on every single request.

Solution

Mandatory gate sequence

AI-SDLC enforces a mandatory artifact-producing gate sequence so quality is process-derived, not prompt-derived.

Solution

Reusable context packs

Engineering standards, test strategy, security rules, and release governance are encoded in context packs — the human supplies only what is genuinely new.

Quality Gates

Ten gates. One traceable trail.

Every change passes through a mandatory gate sequence. Each gate produces a named artifact and appends a machine-readable sdlc-result block.

Control Model

Six autonomy levels

Autonomy is a property of the operating environment, not model capability alone. High autonomy requires tooling maturity, CI/CD gates, observability, and rollback.

Level Name & Role Approval points
How It Works

From intent to shipped — with guardrails

The orchestrator drives gate skills sequentially, propagates state through state.md, and pauses for human approval only when required by the autonomy level or a hard-stop trigger.

Change Classification

Eleven change classes

Every change is classified before any gate runs. The class determines the required gate set and default autonomy level. When classes overlap, the most rigorous applies.
